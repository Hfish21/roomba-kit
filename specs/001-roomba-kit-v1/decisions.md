# Implementation decisions: Roomba Kit V1

Non-obvious calls made during implementation, within the spec and constitution. Newest last.

| # | Decision | Why | Alternative rejected |
|---|---|---|---|
||||||| parent of 2857c61 (Add ServiceContext composition root and service components (T028))
| 1 | `pr-gate`'s diff-size cap counts hand-written lines only. Generated files (`uv.lock`, `docs/reference/*`, `tests/contract/snapshots/*`) are excluded, and each PR body states both counts. | Owner-approved standing override (execution plan D1). Without it, every PR that adds an operation BLOCKs on regenerated reference docs no one reviews by hand. | Separate "regen" PRs: doubles the PR count for no review value. |
| 2 | CI (T005) ships without the `gen_docs.py --check` step; the step is added in the PR that lands T039. | The script doesn't exist until T039, and a red CI on `main` would block every lane. | A stub `gen_docs.py`: a placeholder that passes is a false green. |
| 3 | Ruff excludes `.specify/` (vendored SpecKit scripts). | They're third-party tooling, patched locally, not kit code. | Reformatting them: makes re-applying upstream SpecKit updates harder. |
| 4 | `transport/discovery.py` takes an injected `match: Callable[[str], str \| None]` (SKU → profile ID) instead of importing `profiles.loader`. | The layering contract is `transport → core` only (plan, T003); T017's wording would have made transport import profiles. The service injects `match_profile`. | Allowing `transport → profiles`: weakens the isolation contract for one convenience call. |
| 5 | The CLI root auto-registers any `roomba_kit.cli.*` module exposing `register(group)`, and the API factory exposes `stream_presenters`. | Lets story lanes add CLI extras (wizard, aliases, watchers) and SSE as new files, never editing `cli/main.py` or `api/app.py` (the "new files per story" rule). | Editing a shared index per story: guaranteed merge conflicts across parallel lanes. |
| 6 | Ruff rule `ASYNC109` (async functions taking `timeout`) is ignored repo-wide. | Timeouts are contract parameters (`timeout_s` on wait ops, `request_position(timeout)` in T016), not an ad-hoc pattern `asyncio.timeout` would replace. | Renaming contract params: breaks contracts/operations.md. |
| 7 | `RobotSession` is the only reconnect supervisor. `transport/local.py` makes roombapy single-shot: `connect()` is one attempt, and on a drop the adapter tears the client down and reports `(False, reason)` instead of letting the library reconnect. | roombapy 2.0.2's `RoombaClient` runs its own 1–60 s backoff supervisor after the first connect (read in `roombapy/roomba.py`). Two supervisors would race, and T027's offline-attempt counting (rediscovery after 3, FR-018) needs to see every attempt. | Letting the library supervise and the session only observe: the session can't count failed attempts, so FR-018 rediscovery couldn't trigger. |
| 8 | Normalization checks `evac` (phase or cycle) before `phase=run`. | The i5 reports `run`/`evac` while emptying; R8's rows overlap without an order. | R8's listed order: reports `cleaning` during an evac. |
| 9 | `phase=charge` with `cycle≠none` normalizes to `unknown`. | No R8 row; it's the start→run transient. | `docked`: a false-positive `stop` confirmation. |
| 10 | Clean Base present ⇔ `dock.state` is an int (inferred). | The i5+ Clean Base reports `dock.state` 301–303; the m6's plain dock reports only `{known: true}`. | `dock.known`: true on both docks. |
| 11 | `MissionRef.id` falls back to `""` when `missionId` is missing mid-cycle. | Keeps "mission is None ⇔ cycle none", which `stop` confirmation relies on. | `mission=None`: falsely confirms `stop`. |
| 12 | `find` is confirmed only by an echo newer than the pre-send echo. | The robot keeps the previous `find` echo indefinitely. | Matching the command name alone: instant false confirm. |
| 13 | `dock` confirms on `returning`, `docked` or `charging`. | A docked robot below 100% normalizes to `charging`. | R9 literally (`returning`/`docked`): never confirms a dock that lands while charging. |
| 14 | One shared cloud MQTT session for all robots' timelines (R12/T076). | Hardware spike: two per-robot sessions under one login evict each other (105 drops/90 s); one session subscribed to both robots is stable. | Per-robot sessions (the original R12 decision). |
| 15 | A `credentials.toml` mode broader than 0600 fails with `invalid_request` and a `chmod 600 <path>` hint, on every read, not just at startup. | A user-fixable local misconfiguration, not a kit bug (`internal` = exit 70). Failing closed means a later chmod still blocks secret reads. | `internal`; checking once at startup. |
| 16 | Non-persisted events (`position`) draw seqs from the same counter; a high-water mark is reserved in blocks of 1000 in `event_seq`. | Starting from `max(events.seq)` would reissue position seqs after a restart, so a live consumer at `since=N` would miss events. Gaps are allowed; repeats never. | Persisting every position event; restarting from `max(seq)`. |
| 17 | Robot and cloud credential env vars are parsed by the credentials store; `robots` is excluded from the pydantic-settings env source. `save_config` accepts only the file model, never the env-merged `Settings`. | `ROOMBA_KIT_ROBOTS__<BLID>__PASSWORD` otherwise fails validation of `robots: list`, and secrets stay out of `Settings`. Makes "env never written back" structural. | Secret fields on `Settings`; per-field source tracking. |
| 18 | `credentials.toml` writes are read-modify-write under `flock` on a sibling lock file. | The CLI (`token create`) and the service (`last_used_at`) both write it. | No lock: last writer can drop a new token. |
| 19 | Tokens are `rk_<urlsafe32>`; `last_used_at` persists on first use, then at most every 300 s, and on shutdown. | The prefix lets the redactor mask tokens it has never seen; no file rewrite per request. | Raw random strings; persisting on every request. |
| 20 | Log redaction is installed with `logging.setLogRecordFactory` and only rewrites records it masked. | Covers non-propagating loggers (uvicorn) and handlers added later without breaking `%`-formatting. | Filters on root logger/handlers. |
| 21 | An event stream more than 10,000 events behind is closed. | The consumer resumes with `Last-Event-ID`; memory stays bounded. | Unbounded queues. |
| 22 | `state.db` with a schema version newer than the code refuses to open (`internal`). | Prevents a downgrade silently misreading data. | Ignoring the mismatch. |
| 23 | The transport's connection-callback reason on a drop is an `ErrorCode` value; "held elsewhere" requires the robot at that address to answer a unicast probe with the same robot ID. | Gives the session a stable value to switch on; a different robot at that IP means ours is offline. | Passing library error text; any probe reply counts. |
| 24 | Discovery raises `invalid_request` with a subnet-broadcast hint when every send fails and nothing answered. | Surfaces the VPN `EADDRNOTAVAIL` case instead of an empty list. | Returning `[]`. |
| 25 | Cloud errors never carry library text: credential rejection → `auth_failed`; everything else → `cloud_unavailable` with a reason code. | Library messages can contain account details (Constitution VI). | Passing messages through. |
| 26 | Config gains an additive `[discovery] broadcast` key, and robot entries gain informational `sku`/`firmware`. | FR-018 rediscovery needs a broadcast address that works under a VPN (discovery gotcha); `Robot` needs SKU and firmware before the first connect. | Hard-coding `255.255.255.255`: rediscovery silently fails on this machine. |
| 27 | Kit→protocol command names (`clean`/`clean_rooms` → `start`) live in `profiles/base.py` with per-profile overrides. | Protocol keys belong in profiles or transport, never the session (model-profile contract rule 4). | Mapping in the session or the operations. |
| 28 | `find` is confirmed by any `find` echo when the prior echo was a different command; only a prior `find` needs a strictly newer time. | Echo times are whole seconds; a `find` right after another command shares its timestamp (caught by the session FIFO test). | Always requiring a newer time: false `unconfirmed`. |
| 29 | `RobotSession` keeps one transport per address+password and reconnects it; state listeners get every normalized update uncoalesced, while `state.changed` events are coalesced to ≤1/s. | Derived events (activity, missions) must not lose transitions to coalescing; reusing the transport avoids duplicate callback registration. | Deriving from coalesced `state.changed`; a new transport per attempt. |
| 30 | Derived behaviour registers as a service component (`@component` in `service/components.py`); `load_components()` imports every service module, and the cloud subsystem replaces `ctx.cloud` the same way. | Keeps `service/app.py` closed to story lanes ("new files per story"). | Editing an installer list in `app.py` per story. |
| 31 | A credentials file that turns unreadable at runtime (mode broadened) makes the robot's session `not_configured` rather than crashing its supervisor. | Fail closed without killing the service; startup still refuses (FR-013). | Letting the exception escape the supervisor task. |
| 32 | Connection transitions from `connected` include `held_elsewhere`, `auth_failed` and `connecting` (credentials changed), not only `offline` (data-model.md updated). | They tell consumers *why* the link went, which `offline` alone hides (PR #15 review). | Collapsing every drop into `offline`. |
| 33 | State listeners run inline on the state path and must never await `execute()`/`submit()`. | Ordering of derived events depends on it; a listener awaiting a command would stall state processing for a whole confirmation window. | Running listeners off-path: loses ordering guarantees. |
| 34 | API routes parse `Request` themselves (validation stays in `registry.parse_params`); OpenAPI is built from `openapi_extra` plus component schemas. | FastAPI's own 422 can't leak, and OpenAPI still shows real params, results and the 202/`default` error responses. | Typed FastAPI signatures with FastAPI validation. |
| 35 | Unknown paths/methods return the kit envelope (`invalid_request`) but keep 404/405; 401s carry `WWW-Authenticate: Bearer`. | Every response has one shape, and statuses mean what HTTP clients expect. | 400 for everything; FastAPI's `{"detail"}`. |
| 36 | MCP is attached as a Route at `/mcp` (not a Mount); tools are built by `build_mcp(executor)`. | A Mount redirects `/mcp` → `/mcp/`, breaking clients; the executor lets the stdio proxy (T065) reuse the tools over HTTP. | `app.mount`; tools bound to an in-process context. |
| 37 | MCP tool errors are `"<code>: <message>"`, then a JSON `{"error": …}` line when there's a robot ID or details. | Agents need `candidates`/`valid` rooms; the text still starts with the code. | Code and message only. |
| 38 | CLI option names equal param names (e.g. repeatable `--rooms`); `--room` exists only on the `clean` alias. | Constitution III: identical names across surfaces. | Singularizing list options. |
| 39 | `--json` prints the response bytes unchanged (newline only on a TTY) and, on errors, prints the error body to stdout with the catalogue exit code. | Byte identity when piped (US4 T064); machine consumers always get JSON. | Always appending a newline; errors only on stderr. |
| 40 | `--service-url` defaults to `server.host`/`server.port` from config; `service start` polls that URL. | A re-ported service just works. | Hard-coded 8765. |
| 41 | `service start`/`stop` are idempotent; failed start exits 69 with the last 20 log lines; the daemon is `python -m roomba_kit.cli.main serve` in a new session. | Scripts can rely on them; doesn't depend on the console script being on PATH. | Exit 1 (not in the catalogue); resolving `argv[0]`. |
| 42 | `token_revoke` of an unknown name returns `{revoked: false}` (exit 0). | Mirrors `remove_robot`; there is no `token_not_found` code. | `invalid_request`. |
